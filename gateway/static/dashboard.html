Core contract

The governed path is intentionally narrow.

Scoped authorization

Signed permits bind a subject, tool scope, budget, expiry, and nonce.

discover → authenticate → authorize

Idempotent metering

Retries reuse the same operation boundary so one accepted action is charged once.

invoke → meter

Portable receipts

Governed outcomes can be exported with the issuer key material required for offline verification.

receipt → verify

Durable evidence

Dispatch state and account audit events are persisted for authenticated operator inspection.

audit → govern

Authenticated inspection

Inspect your own permits, receipts, and audit events from a trusted terminal. Keep the key in your environment; do not paste it into a public web page. Set API_URL to the origin serving this page, without a trailing slash; the example below uses the local server default. 

export API_URL="http://127.0.0.1:8000"
export AGENT_MIDDLEWARE_API_KEY='replace-in-your-terminal'

curl --fail-with-body \
  -H "X-API-Key: ${AGENT_MIDDLEWARE_API_KEY}" \
  "${API_URL}/v1/me/permits"

curl --fail-with-body \
  -H "X-API-Key: ${AGENT_MIDDLEWARE_API_KEY}" \
  "${API_URL}/v1/me/receipts"

curl --fail-with-body \
  -H "X-API-Key: ${AGENT_MIDDLEWARE_API_KEY}" \
  "${API_URL}/v1/me/audit/events"

How to read the runtime data

  • upstream_mcp.call_metrics are process-local and reset on restart.
  • upstream_mcp.dispatch_metrics summarize durable dispatch records.
  • A healthy dependency report is operational posture, not evidence of customer usage.
  • The public proof demonstrates one gateway-controlled action, not end-to-end exactly-once behavior for arbitrary upstream side effects.
