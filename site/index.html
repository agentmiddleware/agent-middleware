Each action runs once and leaves a receipt.

Permit

A permit says which tool an agent may use, how much it may spend, and when that ends.

Request key

A request key is a name you give one action so a retry is recognized as the same action.

Receipt

A receipt records the gateway decision and linked outcome. You can check its signature offline. It does not prove the downstream effect.

How it works

From demo key to checked receipt

  • Get a demo key and save the API key and wallet ID.
  • Set the key and wallet ID in the Python commands above, then run the example.
  • The first call creates a permit and prints the receipt ID.
  • For an accepted request key on the configured upstream tool, a retry with the same key returns the original receipt instead of dispatching again.
  • Check the receipt signature offline. See a published sample and verifier.

Limits

Know where the boundary ends

AMW is not exactly once. For a configured upstream tool, one accepted request key permits at most one gateway dispatch and one debit.

delivery_uncertain means we charged this call but do not know if the tool finished. Check the tool directly before you try again. We never resend it on our own.

Receipts sign hashes of the request and response, not the content, and do not prove the tool was right. Read the limits.
